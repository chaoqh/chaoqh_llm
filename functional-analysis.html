Functional Analysis: From Gene Lists to Biological Insight

Differential expression gives you a list of genes that change. Functional analysis answers: what do these genes do together? It identifies overrepresented biological themes — pathways, processes, molecular functions — turning a gene list into testable hypotheses.

Two Complementary Approaches

Over-Representation Analysis (ORA)

Input: a list of "significant" genes (e.g., padj < 0.05). Tests whether a gene set (GO term, KEGG pathway) contains more significant genes than expected by chance. Uses Fisher's exact test / hypergeometric test.

Pros: Simple, fast, intuitive. Cons: Ignores effect sizes; sensitive to significance threshold; treats all significant genes equally.

Gene Set Enrichment Analysis (GSEA)

Input: all genes ranked by a continuous metric (e.g., signed -log10(p) × sign(log2FC), or Wald statistic). Tests whether genes in a set cluster at the top or bottom of the ranked list. No arbitrary threshold.

Pros: Uses full data; detects coordinated small changes; more powerful for subtle effects. Cons: More complex; requires ranked list; correlation structure matters.

Recommendation: Run both. ORA for clear, strong signals; GSEA for subtle, coordinated changes. They often agree but each catches things the other misses.

ORA with clusterProfiler (R)

clusterProfiler is the most popular Bioconductor package for functional analysis.

library(clusterProfiler)
library(org.Hs.eg.db)  # human annotation; use org.Mm.eg.db for mouse, etc.

# 1. Prepare gene lists
# Significant genes (padj < 0.05)
sig_genes <- rownames(resOrdered[resOrdered$padj < 0.05 & !is.na(resOrdered$padj), ])

# Background: all genes tested (after pre-filtering)
bg_genes <- rownames(resOrdered)

# Convert to Entrez IDs (required by clusterProfiler)
sig_entrez <- bitr(sig_genes, fromType="SYMBOL", toType="ENTREZID", OrgDb=org.Hs.eg.db)$ENTREZID
bg_entrez  <- bitr(bg_genes,  fromType="SYMBOL", toType="ENTREZID", OrgDb=org.Hs.eg.db)$ENTREZID

# 2. GO Over-Representation Analysis
ego_bp <- enrichGO(gene          = sig_entrez,
                   universe      = bg_entrez,
                   OrgDb         = org.Hs.eg.db,
                   ont           = "BP",        # "BP", "MF", or "CC"
                   pAdjustMethod = "BH",
                   pvalueCutoff  = 0.05,
                   qvalueCutoff  = 0.05,
                   readable      = TRUE)        # converts Entrez back to symbols

# 3. KEGG Pathway Analysis
ekegg <- enrichKEGG(gene         = sig_entrez,
                    universe     = bg_entrez,
                    organism     = "hsa",       # "hsa"=human, "mmu"=mouse
                    pAdjustMethod = "BH",
                    pvalueCutoff  = 0.05)

# 4. View results
head(ego_bp)
head(ekegg)

# 5. Visualize
dotplot(ego_bp, showCategory=20) + ggtitle("GO Biological Process")
barplot(ego_bp, showCategory=20)
emapplot(pairwise_termsim(ego_bp))  # enrichment map: term similarity network
cnetplot(ego_bp, categorySize="pvalue", foldChange=log2FC_vector)  # gene-term network

# 6. Save
write.csv(as.data.frame(ego_bp), "GO_BP_enrichment.csv")
write.csv(as.data.frame(ekegg), "KEGG_enrichment.csv")

GSEA with clusterProfiler

# 1. Create ranked gene list (all genes, not just significant)
# Metric: signed -log10(pvalue) * sign(log2FC) or Wald statistic
geneList <- resOrdered$stat  # Wald statistic from DESeq2
names(geneList) <- rownames(resOrdered)
geneList <- sort(geneList, decreasing=TRUE)

# Remove genes without Entrez mapping
geneList_entrez <- bitr(names(geneList), fromType="SYMBOL", toType="ENTREZID", OrgDb=org.Hs.eg.db)
geneList_mapped <- geneList[geneList_entrez$SYMBOL]
names(geneList_mapped) <- geneList_entrez$ENTREZID

# 2. GO GSEA
gse_go <- gseGO(geneList     = geneList_mapped,
                OrgDb        = org.Hs.eg.db,
                ont          = "BP",
                nPerm        = 10000,
                minGSSize    = 10,
                maxGSSize    = 500,
                pvalueCutoff = 0.05,
                verbose      = FALSE)

# 3. KEGG GSEA
gse_kegg <- gseKEGG(geneList     = geneList_mapped,
                    organism     = "hsa",
                    nPerm        = 10000,
                    minGSSize    = 10,
                    maxGSSize    = 500,
                    pvalueCutoff = 0.05)

# 4. MSigDB Hallmark GSEA (popular, well-curated)
library(msigdbr)
hallmark <- msigdbr(species="Homo sapiens", category="H") %>% 
            dplyr::select(gs_name, entrez_gene)
gse_hallmark <- GSEA(geneList_mapped, TERM2GENE=hallmark, pvalueCutoff=0.05)

# 5. Visualize GSEA
gseaplot2(gse_go, geneSetID=1:5)  # enrichment curves for top 5 terms
ridgeplot(gse_go) + ggtitle("GSEA Ridge Plot")
dotplot(gse_go, showCategory=20)

Handling Redundancy: Term Similarity and Clustering

GO terms are hierarchical; many significant terms are parent/child or overlap heavily. Use semantic similarity to cluster:

# Pairwise term similarity (Jaccard or semantic)
ego_sim <- pairwise_termsim(ego_bp)

# Cluster terms and plot as tree
treeplot(ego_sim)

# Or enrichment map with clustered layout
emapplot(ego_sim, layout="nicely", cex_category=0.8)

# Simplify: remove redundant terms (keep most significant in each cluster)
ego_simplified <- simplify(ego_bp, cutoff=0.7, by="p.adjust", select_fun=min)
# cutoff = similarity threshold (0.7 = moderate redundancy removal)

Leading-Edge Analysis (GSEA)

For a significant GSEA term, the "leading edge" genes are those that appear before the peak enrichment score — the core drivers of the signal. Extract them:

# For a specific GSEA result (e.g., first row)
leading_edge_genes <- gse_go@result$core_enrichment[1]  # "/" separated Entrez IDs
leading_entrez <- unlist(strsplit(leading_edge_genes, "/"))
# Map back to symbols
leading_symbols <- bitr(leading_entrez, fromType="ENTREZID", toType="SYMBOL", OrgDb=org.Hs.eg.db)
# These are the high-priority genes for follow-up (qPCR, functional assays)

Custom Gene Sets

Test your own hypotheses: literature-curated sets, TF targets from ChIP-seq, protein complexes, etc.

# TERM2GENE format: data.frame with columns "term" and "gene" (Entrez or Symbol)
my_genesets <- data.frame(
  term = c("TF_A_targets", "TF_A_targets", "Complex_B", "Complex_B"),
  gene = c("GENE1", "GENE2", "GENE3", "GENE4")
)

# ORA
enricher(sig_entrez, TERM2GENE=my_genesets, universe=bg_entrez, pvalueCutoff=0.05)

# GSEA
GSEA(geneList_mapped, TERM2GENE=my_genesets, pvalueCutoff=0.05)

Reporting Functional Analysis Results

Include in your paper/supplement:

  • Database versions (GO release date, KEGG release, MSigDB version)
  • Background gene set definition (all tested genes? all expressed genes?)
  • Multiple testing correction method (BH FDR)
  • Significance threshold (typically padj/qvalue < 0.05)
  • For GSEA: ranking metric, number of permutations
  • Redundancy handling (simplify cutoff if used)
  • Top 10–20 terms with gene ratio, p-value, key genes

Common Pitfalls

  1. Using gene symbols instead of Entrez IDs: clusterProfiler requires Entrez IDs. Always convert with bitr().
  2. Wrong background set: Use all genes that passed pre-filtering, not all genes in the genome.
  3. Ignoring redundancy: Reporting 50 GO terms where 40 are parent/child inflates apparent significance.
  4. Threshold hacking in ORA: Changing padj cutoff to get "better" results. Pre-register or justify threshold.
  5. Running GSEA on a pre-filtered list: GSEA needs all genes ranked. Do not pre-filter by significance.
  6. Using outdated annotations: Update org.Hs.eg.db and MSigDB regularly.
  7. Overinterpreting generic terms: "Cellular process", "Metabolic process" are often significant but uninformative. Filter by term specificity (term size 10–500 genes).
  8. Not validating key findings: Enrichment is hypothesis-generating. Validate top pathways with qPCR, Western blot, or functional assays.

Functional Analysis Checklist

  • [ ] DESeq2 results object with gene symbols and Entrez IDs available
  • [ ] Background gene set defined (all tested genes after pre-filtering)
  • [ ] Gene symbols converted to Entrez IDs for all genes
  • [ ] ORA run for GO (BP, MF, CC) with clusterProfiler::enrichGO
  • [ ] ORA run for KEGG/Reactome/MSigDB Hallmark
  • [ ] Redundancy reduction applied (simplify or emapplot clustering)
  • [ ] GSEA run on full ranked list (Wald statistic or signed -log10(p))
  • [ ] GSEA run for GO, KEGG, MSigDB Hallmark
  • [ ] Leading-edge genes extracted for top GSEA terms
  • [ ] Key visualizations generated: dotplot, enrichment map, GSEA curves
  • [ ] Results tables saved with term ID, description, gene ratio, p.adjust, leading genes
  • [ ] Custom gene sets tested (if applicable)
  • [ ] Database versions and parameters documented for methods section
