From Reads to Counts: Alignment and Quantification

After quality control and trimming, the next step is determining where each read came from in the genome or transcriptome, and counting how many reads map to each gene. This produces the count matrix — rows = genes, columns = samples — that is the input for differential expression analysis.

Two Main Strategies

Alignment-based (Genome Alignment)

Map reads to the reference genome with a splice-aware aligner (STAR, HISAT2), then count reads overlapping gene models (featureCounts, HTSeq-count).

Pros: Detects novel splice junctions, enables variant calling, visualizable in genome browser, gold standard for accuracy.

Cons: Slower (15–60 min/sample), larger intermediate files (BAM ~5–15 GB).

Alignment-free (Pseudoalignment / Quasi-mapping)

Map reads directly to the reference transcriptome (Salmon, kallisto). No genome alignment, no BAM file. Estimates transcript abundance via lightweight indexing and EM algorithm.

Pros: Very fast (1–5 min/sample), low memory, no BAM files, transcript-level estimates built-in.

Cons: Cannot detect novel splicing, no genome browser visualization, relies on transcriptome annotation completeness.

Recommendation for this course: Use alignment-based (STAR + featureCounts) for learning — it teaches the concepts and produces inspectable BAMs. For production pipelines with many samples, Salmon/kallisto are excellent and well-validated.

Reference Genome and Annotation

You need two files from the same release (e.g., Ensembl release 110, GENCODE v47):

  • Genome FASTA: Primary assembly (chr1–chr22, chrX, chrY, chrM for human). Avoid "toplevel" which includes patches/haplotypes.
  • Annotation GTF/GFF3: Gene models (exons, CDS, UTRs, gene/transcript IDs, biotypes). Match the genome assembly version exactly.

Download from Ensembl, GENCODE, or UCSC. For human: GRCh38.p14 (Ensembl 110) or hg38 (GENCODE v47).

STAR: Splice-Aware Genome Alignment

STAR (Spliced Transcripts Alignment to a Reference) is the most widely used RNA-seq aligner. Two-step process:

1. Build Genome Index

STAR --runMode genomeGenerate \
     --genomeDir star_index/ \
     --genomeFastaFiles GRCh38.primary_assembly.genome.fa \
     --sjdbGTFfile gencode.v47.annotation.gtf \
     --sjdbOverhang 149  # read length - 1 (for 150 bp reads)
     --runThreadN 16

--sjdbOverhang should be read_length - 1. For mixed read lengths, use the maximum - 1. Index building takes ~30 min and ~35 GB RAM for human.

2. Align Samples

STAR --genomeDir star_index/ \
     --readFilesIn sample_R1.trimmed.fastq.gz sample_R2.trimmed.fastq.gz \
     --readFilesCommand zcat \
     --outFileNamePrefix aligned/sample_ \
     --outSAMtype BAM SortedByCoordinate \
     --outSAMunmapped Within \
     --outSAMattributes NH HI AS nM NM MD \
     --quantMode GeneCounts \
     --twopassMode Basic \
     --runThreadN 16

Key STAR Options

OptionPurpose
--twopassMode BasicNovel junction discovery in pass 1, re-align in pass 2. Recommended.
--quantMode GeneCountsOutputs ReadsPerGene.out.tab (featureCounts-like counts) directly.
--outSAMtype BAM SortedByCoordinateSorted BAM output (required for downstream tools).
--outFilterMultimapNmax 20Max loci per read. Default 10; increase for repetitive genomes.
--alignSJDBoverhangMin 1Minimum overhang for annotated junctions.
--alignIntronMin 20 --alignIntronMax 1,000,000Intron size range. Adjust for organism.

featureCounts: Counting Reads per Gene

If you didn't use --quantMode GeneCounts in STAR, or prefer featureCounts' handling of multimappers and strandedness:

featureCounts -T 16 -p -B -C \
              -a gencode.v47.annotation.gtf \
              -o counts.txt \
              aligned/sample_Aligned.sortedByCoord.out.bam

Key Options

  • -p: Paired-end reads (counts fragments, not reads)
  • -B: Require both ends properly aligned
  • -C: Exclude chimeric reads (different chromosomes)
  • -s 0/1/2: Strandedness: 0=unstranded, 1=forward, 2=reverse. Must match library prep.
  • -t exon -g gene_id: Feature type and attribute (defaults; usually correct for GENCODE)
  • -M: Count multimapping reads (fractionally). Default: ignore multimappers.
  • -O: Allow reads to be assigned to multiple overlapping features.

Output: counts.txt with gene IDs as rows, samples as columns, plus a summary file with assignment statistics.

Salmon: Fast Transcript-Level Quantification

For alignment-free quantification (recommended for large studies):

1. Build Transcriptome Index

salmon index -t gencode.v47.transcripts.fa \
             -i salmon_index \
             --type quasi \
             -k 31

2. Quantify Samples

salmon quant -i salmon_index \
             -l ISR \  # library type: I=inward, S=stranded, R=reverse (read 1 = antisense)
             -1 sample_R1.trimmed.fastq.gz \
             -2 sample_R2.trimmed.fastq.gz \
             -p 16 \
             --validateMappings \
             -o salmon_out/sample

Output: quant.sf with transcript-level TPM, NumReads, and effective length. Use tximport (R) to summarize to gene level for DESeq2/edgeR.

Comparing Count Matrices

Regardless of method, you need a gene × sample count matrix for differential expression. Key checks:

CheckExpectedConcern If
Genes with > 0 counts in all samples12,000–18,000 (human)< 8,000
Median counts per sample10–30 million (for 30M reads)< 5M or > 50M
% assigned reads (featureCounts)60–85%< 50%
% multimapping (featureCounts)5–15%> 30%
% ambiguous (overlapping genes)1–5%> 10%
Correlation between replicatesPearson > 0.95 (log counts)< 0.90

Handling Multimapping Reads

  • Genomic multimappers: Reads mapping to multiple loci (paralogs, repeats). STAR reports NH tag. Options: ignore (default), count fractionally (-M in featureCounts), or assign probabilistically (Salmon/kallisto do this via EM).
  • Multimapping across gene models: Overlapping genes on opposite strands. Stranded libraries resolve this; unstranded libraries need -O or fractional assignment.

Best practice: For DESeq2/edgeR, use unique-mapping reads only (default featureCounts). Multimapper handling introduces assumptions; unique reads are cleaner for differential expression.

Gene ID Conversion

Count matrices use Ensembl gene IDs (ENSG00000123456). For downstream analysis and reporting, convert to gene symbols:

# R with biomaRt or AnnotationDbi
library(org.Hs.eg.db)
ids <- rownames(counts)
symbols <- mapIds(org.Hs.eg.db, keys=ids, column="SYMBOL", keytype="ENSEMBL", multiVals="first")
# Keep only genes with symbols
counts <- counts[!is.na(symbols), ]
rownames(counts) <- symbols[!is.na(symbols)]

Always keep the Ensembl ID as a column; symbols change between releases.

Alignment vs. Quantification Checklist

  • [ ] Reference genome FASTA and GTF from same release downloaded
  • [ ] STAR genome index built with correct --sjdbOverhang
  • [ ] All samples aligned with --twopassMode Basic
  • [ ] BAM files sorted by coordinate, indexed (samtools index)
  • [ ] featureCounts run with correct strandedness (-s 0/1/2)
  • [ ] Count matrix generated: genes × samples, integer counts
  • [ ] Assignment rates > 60% for all samples
  • [ ] Replicate correlation (log counts) > 0.95
  • [ ] Gene IDs converted to symbols for reporting (Ensembl IDs retained)
  • [ ] Count matrix saved as counts_matrix.txt (tab-delimited)
